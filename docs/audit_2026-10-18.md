## Баги

1. ✅ `MEDIUM | bug | scripts/key_daemon.py:2045-2497, 3039-3062` — исключение в
   пост-обработке прогона убивает демон. Внешний `try` в `run_campaign` — без
   `except` (только `finally: lock.release()` :2496-2497); `_commit_run_results`
   (:2283) и финализация (:2483-2493) вне обёртки; `main()` вызывает
   `run_campaign` без try (:3039-3061); `__main__` ловит только
   KeyboardInterrupt (:3093). Триггеры: `TimeoutExpired` из `run_qa_batch`
   (:1286-1291), KeyError разбора QA-JSON (:1265-1270), сбои finalize/digest.
   Последствие: traceback и выход процесса вместо `NEEDS_ATTENTION` — кампания
   встаёт до ручного перезапуска. Фикс: `except Exception` вокруг :2283-2493 →
   NEEDS_ATTENTION + `save_json` (как уже сделано для in-process сбора).

2. ✅ `LOW | bug | scripts/key_daemon.py:1265-1270` — `_parse_qa_json_report`
   не защищён от нарушения контракта: `r["pid"]`, `r["verdict"]`, `i["code"]`
   прямым доступом; fallback на stdout срабатывает только при отсутствии ключей
   верхнего уровня (:1254-1256). Частичный JSON → KeyError → маршрут находки №1.
   Фикс: `.get` + проверка типов, иначе `return None` (fallback).

3. ✅ `LOW | bug | ozon_collector/parallel.py:411-413 ↔ 1509-1512` — гонка
   lost-update на `wctx.batch_completed`: reader-поток делает `extend`, главный
   цикл — check → `completed_indexes.update(...)` → rebind `= []`. Индексы,
   дописанные в осиротевший список, теряются → `_requeue_unfinished`
   (:1514-1532) вернёт уже собранный товар → повторный сбор, возможен дубль.
   Условие: совпадение окон при `done_batch` (часы работы демона). Фикс: лок на
   воркер (или `queue.SimpleQueue`), дренаж под тем же локом.

4. ✅ `LOW | bug | scripts/key_daemon.py:799-819` — PidLock: окно пустого файла.
   Победитель создаёт файл `O_EXCL` (:801), пишет JSON только :812-817.
   Проигравший в этот момент читает пустой файл → `load_json` = None → трактует
   как stale → `unlink` (:808) → его повторный acquire успешен → два демона над
   одним `data_dir`. Фикс: при `None` — пауза 50-100 мс и перечитать; всё ещё
   пусто — stale.

5. 📋 `LOW | bug | ozon_collector/ocr.py:148-183, 424-427` — Tesseract через
   `pytesseract` без `timeout=`; зависший бинарник блокирует `ex.map` воркера.
   Требует runtime-проверки (нужен зависший tesseract). Фикс: timeout/обёртка с
   гарантированным убийством процесса.

6. ✅ `LOW | bug | ozon_collector/search.py:245-252 ↔ 281-287` — Ctrl+C теряет
   `skipped_no_reviews`: `CollectionInterrupted` несёт только `seen`; `no_reviews`
   (:256, :281-285) не доезжает ни до отчёта, ни до `combined`. Фикс: положить
   `no_reviews` в исключение или recovery-телеметрию.

7. ✅ `LOW | deadcode | ozon_collector/parallel.py:1870` — `shards =
   shard_items(items, parallel)` перекрыто на :1927-1928 (`_rebuild_shards`) без
   промежуточного чтения; комментарий :1886-1889 сам говорит, что список не
   раздаётся статически. Фикс: удалить строку.

8. 📋 `LOW | contract | ozon_collector/search.py:875-884 vs docstring :851` —
   `new_tab_attempts`/`recovery_kind` присваиваются только на общем выходе
   (:1124-1126); у abort-записей их нет. Потребителей без `.get` не найдено —
   расхождение докстроки и данных. Фикс: добавить поля (0/None) в abort-записи.

Ложные тревоги (проверены, это не баги):

   `_launch_log_tail` (browser.py:277-279). Комментарий cdp.py:256-258 сам
   фиксирует прошлый рассинхрон («recycle воркера терял прокси»). → один хелпер.

   регресс SW_MINIMIZE (уже случался 2026-10-16). → cdp зовёт канон.
