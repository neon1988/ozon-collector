## Что было сломано

Вердикт снятия признавал успех ТОЛЬКО по `captchaDone=true` в URL. Текущее
поколение капчи (v10, кусочек без трека) после верного дропа снимает
челлендж из DOM и перезапрашивает выдачу на месте — навигации не бывает.

Журнал `20260929.jsonl` (486 записей, 86 вызовов):

- 80 завершённых драгов, 64 легли в лунку (|err|≤1px, settled) → **драг точен**;
- 65 из 66 дропов, снявших челлендж, были пиксельно точными (98.5%)
  → **детектор верен**;
- успехом засчитаны 3 из 86 (3.5%) → терял только вердикт.

Побочный ущерб: каждый отвергнутый кандидат ждал 24s (`_confirm_solved` 6s +
`_grace_resolve` 18s) ради маркера, которого не бывает. На цикл выходил
**1.07 дропа вместо трёх** — бюджет попыток не выбирался.

## Исправление

`puzzle_dom._classify(url_done, challenge_gone, stub)` — чистый вердикт:

- `done` — URL несёт `captchaDone=true` (старое поколение со слайдером);
- `unblocked` — челлендж снят из DOM, страница не заглушка (текущее v10);
- `no` — челлендж жив либо страница подменена заглушкой.

Подтверждение живыми: `via=unblocked` 9, `via=done` 25 из 34 успехов.
**Новый путь дал 9 побед, которые старый код выбросил бы** (4/7 = 57% в первом
прогоне). Ни одного ложного `unblocked`: все 29 провалов имели `verdict=no`,
то есть были честными отрицаниями, а не потерянными победами.

Заглушка осталась гейтом (`_stub_page`). Ветка `solve_puzzle`, где пазла в
кадре нет, намеренно оставлена на одном URL-маркере: иначе обычная страница
без капчи дала бы ложный успех.

## Как спровоцировать пазл (важно)

Продуктовые страницы сами по себе пазл НЕ вызывают:

| Способ | URL | Пазлов |
|---|---|---|
| `solve_live2.py` 1 вкладка, задержка 1.0s, куки чистим | 36 | **0** |
| `puzzle_hunter.py` 8 вкладок, задержка 0.16s, куки чистим | 652 | **34** |

Триггер **rate-based**, а не по профилю. Последовательные заходы с паузой
секунды не давят. Рабочий рецепт:

```
python tools\puzzle_hunter.py --port 9444 --tabs 8 --limit 30 --max-seconds 1500
```

Порог: примерно 1 пазл на 15-20 URL при 8 вкладках.

Изоляция: хантер работает на своём профиле `ozon-profile-solve-live2` и своём
порту, production-профиль `ozon-profile` и CDP 9222 не трогает.

## Ловушки

- **Порт 9337** (дефолт `solve_live2.py`) попадал в зарезервированный
  диапазон Windows 9255–9354 → WSAEACCES. Резервация динамическая: на
  2026-09-30 диапазон был свободен, 9337 и 9444 оба FREE. Проверять перед
  прогоном: `netsh interface ipv4 show excludedportrange protocol=tcp`.
  Безопасный выбор — **9444**.
- `puzzle_hunter.py` **не имеет** флага `--yes` (в отличие от `solve_live2.py`)
  — вызов с ним падает с `unrecognized arguments`.
- `OZON_ATTEMPT_LOG` и `OZON_PUZZLE_DIAG_DIR` стоит уводить в
  `<проект>/.tmp/<прогон>/`, иначе новый журнал смешивается с базовым
  `20260929.jsonl`, на котором построен разбор.
