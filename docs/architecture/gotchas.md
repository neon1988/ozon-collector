# Ловушки ozon-collector — ЧЕРНОВИК, ТРЕБУЕТ РЕВЬЮ

> Статус: **черновик, требует ревью**. Собрано из существующей архитектуры.
> Каждый пункт указывает основание и цену ошибки.

## Браузер

- **Chromium — единственный движок.** Ozon отдаёт заглушку «похоже, нет
  соединения» на первом `goto` любой сессии geckodriver/Marionette.
  Флаг webdriver причиной не является: Chromium с `--enable-automation`
  и `webdriver=true` проходит.
  **Основание:** `architecture.md` §4; `anti_bot_architecture.md`.
  **Цена ошибки:** часы отладки впустую, ложные «сети».

- **Порт 9333 занять нельзя** — попадает в зарезервированный диапазон Windows
  9255–9354 и даёт WSAEACCES. Альтернативные браузеры — **9444**.
  **Основание:** `architecture.md` §4. **Цена ошибки:** Chromium не поднимается.

- **`ms-playwright/chromium` через launch нестабильна** — не использовать.
  **Основание:** `architecture.md` §4.

- **«Мини-плитка» над панелью задач = свёрнутое TOOLWINDOW-окно.** Windows
  рисует свёрнутое окно с `WS_EX_TOOLWINDOW` полоской ~160×28 с крестиком
  (живой замер 2026-10-16: `vis=True icon=True rect=0,1004,160,1032`), кадры
  на свёрнутом не идут (screenshot TimeoutError 6с). Окна коллектора
  показываются не свёрнутыми: либо скрыты с рождения, либо парковка; прятать
  только `SW_HIDE` (0): скрытое с рождения окно кадры отдаёт (0.06с),
  показанное и затем скрытое — снова через ~9с. `SW_MINIMIZE` /
  `SW_SHOWMINNOACTIVE` в коде коллектора запрещены (стерегут
  `test_launch_scripts` / `test_collector_tray` / `test_window_policy`).
  Offscreen-парковка кадры и CDP-ввод не рвёт вовсе (замер 2026-10-16;
  повторно 2026-10-18: `park_offscreen` + `bring_onscreen` — рабочий канон,
  CDP bounds следует за позицией, `visibilityState=visible`, screenshot OK).
  **Chrome показывает окно сам на `Target.createTarget`** (`ctx.new_page()` →
  серый пустой прямоугольник `#202020` с × на 10-30 мс, пока WinEvent-хук не
  погасит; замер 2026-10-18). `background:true` НЕ помогает (окно всё равно
  показывается, а Playwright не видит «сырой» таргет), `DWMWA_CLOAK` —
  `DwmSetWindowAttribute` = `E_ACCESSDENIED`. Лечится только парковкой окна за
  краем виртуального рабочего стола; любой показ обязан вернуть его на экран.
  Щель «Chrome создал окно на дефолтной позиции → лаунчер запарковал»
  закрывается `--window-position` (координата считается по
  `GetSystemMetrics(76/78)` до CreateProcess): окно рождается за экраном, и
  даже первый показ Chrome невидим (замер 5 мс: первый `vis=True` — уже на
  `left=-1540`).
  **Основание:** live-замеры 2026-10-16; `docs/tasks/current.md` «Четвёртый
  заход». **Цена ошибки:** два захода мимо (охота на «тосты» и «сторонние
  процессы»), повисший пазл при `drops=0`.

- **Permission-бабл Chrome — отдельное ВИДИМОЕ окно даже при скрытом главном.**
  Живой замер 2026-10-16: через ~2с после загрузки ozon-страницы Chrome создаёт
  окно `title='www.ozon.ru запрашивает разрешение на:'` (`vis=True noact=False
  tool=True rect=1218,136,1552,442`) и держит его открытым — владелец видит
  «плитку» поверх своих окон; главное окно при этом остаётся скрытым
  (`vis=False noact=True`), кадры идут. Лечится флагом
  `--deny-permission-prompts` (запросы авто-отклоняются, UI не создаётся;
  семантика: chromium `components/permissions/README.md`): с ним тот же
  сценарий окна не создаёт. Побочный эффект — `Notification.permission ===
  'denied'` (JS-наблюдаемо), как у живого пользователя, нажавшего «блокировать».
  **Основание:** live-замеры 2026-10-16 (`.tmp/watch_pop_probe.py`);
  `docs/tasks/current.md` «Пятый заход». **Цена ошибки:** «видимые окна»
  списывались на коллектор, а рисовал их сам Chrome.

- **Вкладка одна на весь прогон.** `Session` берёт `ctx.pages[0]`; сторонние
  зонды во время прогона вкладку коллектора не трогают.
  **Основание:** `architecture.md` §4. **Цена ошибки:** порча прогона.

## Процессы

- **PID reuse.** Убивать браузер только со сверкой identity
  (PID + cmdline + браузер-маркер), иначе убьёшь чужой процесс.
  **Основание:** `architecture.md` §4; `process.py`.

- **Проверять демона по файлам и логам, а не по pid.** Запуск через
  `Start-Process` переживает таймаут шелла — pid живёт, процесс мог умереть.
  **Основание:** `architecture.md` §9.

## Отзывы и сессионный срез

- **Срез отзывов серверный.** У неавторизованного профиля Ozon отдаёт единицы
  отзывов независимо от транспорта: DOM и JSON API дали одинаковые 4 uuid при
  `paging.total = 257 707`. Настоящая пагинация требует токенов страницы
  (`sh`, `start_page_id`); без них `layout_page_index` игнорируется.
  **Синтезировать пагинацию «похожим URL» нельзя.**
  **Основание:** `architecture.md` §10 «Сессионный срез отзывов».
  **Цена ошибки:** месяцы на ложную гипотезу пагинации.

- **`stars = 0` — не отдельный тип отзыва.** Основная масса — потерянные звёзды
  или архивная разметка (старше ~365 дней). Тип `rating_only` не вводился.
  **Основание:** `architecture.md` §5 (шаг 5).

- **Ozon размонтирует верхние карточки при прокрутке.** Top-up виртуализации
  обязателен: двухфазный обезд (подъём к вершине, затем спуск), слияние
  через `_merge_topup`.
  **Основание:** `architecture.md` §5 (шаг 6).

- **Затворы пустоты проверяются до всякой прокрутки.** Явные
  `rating_count == 0`, `variant_count == 0`, либо отсутствие счётчиков вместе
  с 0 карточками на странице отзывов → `stop_reason=no_cards_no_count_hint`.
  **Основание:** `architecture.md` §5 (шаг 2). **Выигрыш:** 70–90 с на пустом товаре.

## Контракты

- **`combined.json` пишется всегда**, когда задан `--out-raw`, включая
  challenge-storm с полем `aborted`. Это контракт для супервизора.
  **Основание:** `architecture.md` §8.

- **Демон читает JSON-контракт, а не stdout.** Машинный вывод — отчёт
  `--report-json`; сводная строка `[qa] ...` только для человека.
  **Основание:** `architecture.md` §10.

- **Challenge-storm в CLI** — 3 `AccessChallengeError` подряд, самопрерывание
  прогона. Демон поверх CLI трактует это как короткую фиксированную паузу
  (`--challenge-pause`), а не как длинный растущий cooldown.
  **Основание:** `architecture.md` §9.

## Тесты

- **`test_baseline_matches_source_raw` падает и на чистой HEAD** — дрейф
  baseline, помечен `xfail`. Не блокирует CI. Не «лечи» перезаписью baseline
  молча: это скроет расхождение источника данных.
  **Основание:** `architecture.md` §13.
