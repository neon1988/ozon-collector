# Инварианты ozon-collector — ЧЕРНОВИК, ТРЕБУЕТ РЕВЬЮ

> Статус: **черновик, требует ревью**. Собрано из существующей архитектуры,
> не из живого кода. Каждый пункт указывает основание — проверь его перед тем,
> как считать правилом.
>
> Нарушение любого инварианта = нельзя мержить и нельзя коммитить результат,
> пока не восстановлено.

## I1. Собранное = отзывы именно этого варианта товара

Нативный фильтр Ozon «Этот вариант товара» включён; отзывы чужих вариантов
отбрасываются. Собранное число отзывов должно совпадать с `variant_count`.

Допуск: при `variant_count ≤ 100` — `max(1, round(vc × 0.03))` (стена логина
плавает ~96–99); при `vc > 100` — требуется ≥90 и равномерность сортировок
(≥70% от лучшей).

Нарушение → `VariantShortError`, товар считается несобранным, raw удаляется.

**Основание:** `architecture.md` §1 (правило 1), §5 «Правило брака
`variant_review_problems()`».

## I2. Никакого headless и никакого API

Ozon FAB блокирует автоматических клиентов. Единственный путь — живой видимый
Chromium с реальным профилем, управление через CDP `http://127.0.0.1:9222`.

**Основание:** `architecture.md` §1 (правило 2), §4.

## I3. Data Quality Gate

После каждого прогона `scripts/qa_raw.py` проверяет целостность данных.
`FAIL` считается браком. Тихий пропуск брака исключён.

**Основание:** `architecture.md` §1 (правило 3), §10.

## I4. Достоверность QA в демоне (инвариант K4)

- `products == len(batch)`
- `ok + warn + fail == products`
- при `fail > 0` поле `per_pid` покрывает все PID батча

Нарушение → статус `NEEDS_ATTENTION`, терминально. Проверяется и в живом QA,
и в финальном QA финализатора.

**Основание:** `architecture.md` §12 «Инварианты K4».

## I5. Источник истины (П1) — canonical raw

`valid_pids` содержит только PID, у которых существует `data/{pid}_raw.json`
с актуальным вердиктом `OK`/`WARN`. При изменении или удалении файла
невалидность возникает по `mtime`.

**Основание:** `architecture.md` §12 «Источник истины (П1)».

## I6. Единственный источник состояния кампании

Состояние — `data/campaigns/{campaign}/progress.json`, запись атомарная.
При `resume` конфигурация берётся из поля `run_cfg` манифеста,
а не из новых аргументов командной строки.

**Основание:** `architecture.md` §12.

## I7. `WALL_LIMITED` — не брак

`WALL_LIMITED` означает ожидаемое ограничение неавторизованного Ozon при
`variant_count > 100`. Трактовать как брак запрещено: иначе валидные PID
уедут в массовый rescan.

**Основание:** `architecture.md` §6; §10 («коды INFO не меняют вердикт»).

## I8. `NEEDS_ATTENTION` терминален

Демон не затирает `NEEDS_ATTENTION` финализатором никогда.

**Основание:** `architecture.md` §12 «Итоговые статусы».

## Что ещё не вынесено

Резерв `target + reserve_count`, детерминированный брак → permanent,
`max_rescans` на PID описаны в `key_daemon_architecture.md`. Кандидаты в
инварианты — после ревью.
