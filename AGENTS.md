Глобальные правила для всех проектов: `%USERPROFILE%\.config\opencode\AGENTS.md`.
Читаются всегда. Этот файл содержит **только отличия** проекта — полных копий
глобальных правил здесь намеренно нет.

## Инварианты — не нарушать

1. **Собранное = отзывы именно этого варианта товара.** Нативный фильтр Ozon
   включён, число отзывов совпадает с `variant_count` (допуск 3%, но не меньше 1).
2. **Только живой Chromium с настоящим окном + CDP `127.0.0.1:9222`.** Headless,
   API и geckodriver/Marionette запрещены — Ozon отдаёт антибот-заглушку.
   Свёрнутое (**minimized**) окно под Windows не отдаёт кадры композитора,
   `page.screenshot` виснет до таймаута (замер 2026-10-08: 6с ×3 подряд),
   `captureScreenshot(fromSurface=false)` — 210с и плоская заливка; **скрытое
   `SW_HIDE` окно кадры отдаёт** (штатный режим сбора). Солвер окно НЕ
   показывает: `ensure_render_window` только скрывает (канон 2026-10-16).
   Скрытое окно **паркуется за краем виртуального рабочего стола**
   (`window_policy.park_offscreen`): Chrome показывает окно сам (старт,
   `Target.createTarget` → `ctx.new_page()`, пазл), гашение опаздывает на
   10-30 мс и окно успевает мигнуть серым пустым прямоугольником (замер
   2026-10-18). Любой штатный показ возвращает окно на экран
   (`bring_onscreen`; трей — свой `BringOnScreen`). Окно **рождается** за
   экраном (`--window-position`, координата по `GetSystemMetrics(76/78)`):
   щели «Chrome создал окно → лаунчер запарковал» нет, первый показ Chrome
   уже невидим. CDP-модель следует за позицией, скриншоты и
   `visibilityState=visible` не страдают (живой стенд).
3. **QA-гейт обязателен.** `scripts/qa_raw.py` после каждого прогона; `FAIL` =
   брак, тихий пропуск брака исключён.
4. **Состояние кампании живёт только в** `data/campaigns/{campaign}/progress.json`.
   При `resume` конфиг берётся из `run_cfg` манифеста, а не из новых аргументов CLI.
5. **`WALL_LIMITED` — не брак**, а ожидаемое ограничение неавторизованного Ozon
   при `variant_count > 100`.
6. **Окна сбора — два режима, переключатель в трее** (слова владельца
   2026-10-16). hidden (по умолчанию): ни одно окно сбора не показывается.
   visible («Развернуть окна сбора»): все окна сбора показаны обычными окнами
   с кнопками панели задач; сторож и пазл-съёмка не перечат пользователю.
   Режим — файл `data/window_visible.flag` (`window_policy.USER_VISIBLE_FLAG`):
   `1` — visible, `0` — hidden, нет файла — решает env. Консольный env задаёт
   стартовый режим, после старта главный трей: явный `0` сильнее
   `OZON_KEEP_WINDOW` (решение владельца 2026-10-19). Пишет только трей,
   сбрасывает `key_daemon` при старте сбора. «Выход» в трее останавливает и
   сбор (Ctrl+C демону; `collector_tray.ps1 -SendCtrlC`), а при сбое WMI
   проверяет демона по `data/key_daemon.pid` (pid + started_at).

Формулировки и основания: `docs/architecture/invariants.md`.

## Проверка

Единая точка проверки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify.ps1 -Quick
```

Порядок: синтаксис → CLI → тесты. Полный прогон идёт через
`scripts/run_tests_guarded.py --timeout 900`: дефолтный таймаут pytest в 300 с
**не проходит** весь набор, а reaper в этом скрипте снимает потомков и сирот
прошлых прогонов — иначе браузеры держат каталог профиля.

**`-Quick` не доказывает, что тесты зелёные** — он их не запускает и печатает
`QUICK OK (syntax + cli only; TESTS WERE NOT RUN)`. Доказательством проверки
считается только полный прогон (`ALL GREEN`). На 07.10.2026 `-Quick` печатал
`QUICK GREEN` и выходил с кодом 0, даже когда шаги провалились, — это ввело в
заблуждение и попало в `docs/tasks/current.md` как «проверка пройдена».

Пока работает демон, порты 9222-9230 заняты, и два портовых теста падают по
этой причине; прогон с исключением:
`python scripts\run_tests_guarded.py --timeout 900 -k "not worker_ports_are_not_reserved_by_windows and not port_bindable_distinguishes_reserved_from_occupied"`.

QA одного товара — `python scripts/qa_raw.py --pids <pid>`, это уже не проверка
кода, а проверка данных.

## Гигиена: не оставлять мусор (просил пользователь 2026-10-02)

- **Процессы.** Долгий запуск — только через `scripts/run_tests_guarded.py`: в нём
  reaper снимает потомков pytest и сирот прошлых прогонов. Ручной `python`, `npm`,
  браузер или пайплайн — снять самому в конце задачи. Прецедент: `awk.exe` из
  Git Bash провисел с 27.09 (121 ч CPU, родитель-сирота), потому что его
  отладочный скрипт удалили, а процессы остались; зациклился он внутри собственной
  программы — она вставляла текст внутрь backtick'ов и снова подходила под свою
  регулярку. **Зависший отладочный пайплайн = баг на всю машину, а не мелочь.**
- **Временные файлы.** Только `.tmp/` проекта, и убираются в конце задачи. Результат
  измерения, на который опирается вывод, живёт в `docs/tasks/current.md`, а не в
  `.tmp/`: артефакт нельзя считать памятью через месяц.
- **Уборка — часть задачи, а не отдельная просьба.** Закончил измерение — убил
  процесс, удалил свой скрипт, сказал пользователю, что осталось.

## Ловушки (самые дорогие)

- **Порт 9222 (и 9223-9230) может уйти в зарезервированные диапазоны Windows.**
  Живой замер 2026-10-03: `netsh int ipv4 show excludedportrange protocol=tcp`
  показал диапазон **9172-9271**, куда попали и main, и все воркеры. bind даёт
  `PermissionError [WinError 10013]` (WSAEACCES), Chromium не может поднять
  DevTools, и демон сыплет «Chromium EXITED, CDP never came up» при **свободном**
  порте — виновник не процесс, а само ОС (WSL/Hyper-V/Docker пересчитывают
  резервации при старте). Старый текст подсказки «порт занят старым» уводил в
  сторону. База теперь выбирается динамически (`process.cdp_port_base()`, фоллбэк
  9444+), переопределяется `OZON_CDP_PORT` / `OZON_WORKER_CDP_PORT`. Проверить:
  `python .tmp/port_check.py` или `netsh … excludedportrange`.
- **Свёрнутое окно Chromium не отдаёт кадры вообще.** Замер 2026-10-08: на
  `normal` скриншот 0.05с и std 32, на `minimized` — таймаут 6с подряд, а
  `captureScreenshot(fromSurface=false)` отдал белую заливку std 0.0 через 210с.
  `page.bring_to_front()` НЕ помогает, помогает только
  `Browser.setWindowBounds windowState=normal` (солвер зовёт сам через
  `ensure_render_window`). Проверить:
  `python -c "from ozon_collector import puzzle_capture as p; ..."`.
  Симптом в бою был неочевидный: 8 съёмок по 5с съедали `PUZZLE_BUDGET_S=60`
  до первого драга, и лог писал «вкладка зависла» при `drops=0`.
- **«Мини-плитка» владельца = свёрнутое TOOLWINDOW-окно.** Windows рисует его
  полоской с крестиком над панелью задач (замер 2026-10-16: `icon=True
  rect=0,1004,160,1032`), кадров нет. Окна коллектора прячутся только
  `SW_HIDE`; `SW_MINIMIZE`/`SW_SHOWMINNOACTIVE` запрещены (стерегут тесты).
  Второй источник видимых окон — permission-бабл Chrome («запрашивает
  разрешение на:»): отдельное ВИДИМОЕ окно при скрытом главном; глушится
  `--deny-permission-prompts` (флаг в обоих лаунчерах).
- Порт 9333 попадает в зарезервированный диапазон Windows (WSAEACCES) →
  альтернативные браузеры вешать на **9444**.
- `ms-playwright/chromium` через launch нестабильна — не использовать.
- Убивать браузер можно только со сверкой identity (PID + cmdline + маркер),
  иначе убьёшь чужой процесс после переиспользования PID.
- Состояние демона проверяется по файлам и логам, а не только по наличию pid.
- Сессионный срез отзывов серверный: анонимный профиль получает единицы отзывов
  независимо от транспорта, синтезировать пагинацию «похожим URL» нельзя.

Полный список: `docs/architecture/gotchas.md`.

## Данные и секреты

- В `.gitignore`: `data/`, `logs/`, `docs/qa/`, `docs/digests/`, `.agents/`, `tools/`, `.tmp/`.
- **Профили Chromium — в `.tmp/profiles/`, и это НЕ мусор.** Решение владельца
  07.10: перенос из `%LOCALAPPDATA%\opencode` (там же лежат профили avito и
  других проектов). Задаётся `OZON_PROFILE_BASE` на уровне User; при новом
  запуске без env профили уедут обратно в `LOCALAPPDATA` и потеряют куки.
  Содержит `ozon-profile` + `ozon-profile-worker-1..8` с пройденной 18+
  проверкой. Правило «в `.tmp` только временное, убирать в конце задачи» здесь
  НЕ действует: удаление = заново 18+ и холодная сессия (Ozon подсовывает пазл).
- `.env`, куки, токены в коммит не попадают: проверяй `git diff --cached` перед коммитом.

## Размер профилей

92% профиля — воспроизводимый кэш Chromium (`Default/Cache` + `Code Cache` +
BrowserMetrics + component_crx_cache), а не состояние сессии: Cookies/Local
Storage/Sessions на 9 профилей — 79 МБ. Живой замер 07.10: без потолка 880 МБ на
воркер, **6.7 ГБ на 9 профилей**; после уборки и с потолком — **268 МБ на все 9**.

- Потолок на браузер: `--disk-cache-size` в `launch_chrome.ps1`/`.sh`,
  дефолт 100 МБ, переопределяется `OZON_DISK_CACHE_MB`. Флаг не JS-наблюдаемый,
  отпечаток страницы не меняет. **Режет только `Default/Cache`** — без уборки
  папка всё равно растёт до ~400 МБ на воркер.
- Автоуборка: `parallel.preflight_check` → `_gc_profile_caches()` чистит профили
  воркеров перед стартом, порог `GC_MIN_MB` (200 МБ). Точка вызова выбрана по
  инварианту, а не по удобству: осиротевшие браузеры к этому моменту уже убиты,
  новые ещё не подняты. Уборка **не роняет сбор** при ошибке.
- Ручная: `python scripts\clean_profile_cache.py --apply` (dry-run по умолчанию).
  Список каталогов живёт в `ozon_collector/profile_gc.py` — он нужен и демону, и
  скрипту, дублировать его опасно.
- Профиль с живым Chromium уборка **пропускает** (удаление у живого Chromium
  ломает профиль); не удалось определить живость — тоже пропуск.
- `STATE_DIRS` (Cookies/Local Storage/Sessions/IndexedDB/Storage/Preferences/
  Network/Web Data) в `JUNK_DIRS` не входят; это проверяет тест
  `test_profile_gc.py::TestWhitelistSafety`.
