## Правила работы (кратко, детали — в AGENTS.md)

- Проверка: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify.ps1`
  (`-Quick` без тестов). Полный прогон идёт через `scripts/run_tests_guarded.py`.
- QA данных: `python scripts/qa_raw.py --pids <pid>` — проверка товара, не кода.
- Не оставлять мусор: временные файлы только в `.tmp/`, процессы и скрипты
  убираются в конце задачи.
- Агент не убивает чужие процессы и не трогает браузеры пользователя.

## Ограничения Ozon (проверено замерами)

- **Единственный рабочий транспорт** — живой видимый Chromium + CDP
  `127.0.0.1:9222`. FAB режет webfetch/автоклиентов; headless и geckodriver/
  Marionette отдают антибот-заглушку.
- **Базовое окно отзывов ≈ 96** (не 97). Оно дрейфует между днями и зависит от
  Ozon, а не от профиля: сравнивать можно только внутри одного дня и одной
  среды. Baseline после дрейфа пересобирать из свежего сбора, иначе получишь
  ложные missing/extra.
- **Без авторизации Ozon отдаёт максимум ~96-100 отзывов** (`WALL_LIMITED`).
  Поэтому карточки с `variant_count > 100` в неавторизованном профиле
  принципиально не дают полного совпадения с инвариантом I1.
- Сортировка отзывов через URL (`?sort=`) **не работает** — только клик «Дальше».
- Выборка отзывов смещена к негативу: рейтингу доверять виджету
  `webReviewProductScore`, а не своей выборке.
- `search` берёт товары **только** из `tileGridDesktop`; блоки «Вы смотрели» и
  «Возможно, вам понравится» в выборку не попадают.
- **HEAD 403 ≠ бан IP.** Ozon отдаёт challenge с кодом 200, а HEAD получает
  405/403. Бан засчитывается только если HEAD **и** GET (`Range`) оба в
  `IP_BLOCK_STATUSES`; иначе это отказ WAF на метод (фикс P4, ревизия 2.9).

## Правила пагинации и скролла

- `SCROLL_STEP_PX=1500`, `SCROLL_PAUSE_MS=400` — измеренный лидер
  (81.0с против 192.2с у анкера 900/1600/6).
- **Шаг 2000px небезопасен**: lazy-чанк проскакивается, `missing ≠ 0` и
  сходимость срабатывает преждевременно. Лимитирует именно шаг, не пауза.
- Правило шторма: после повторного challenge — **стоп 12-24 ч**, без дальнейших
  попыток. Большой прогон (`limit ≥ 100`) — только после паузы и smoke,
  начинать с `--parallel 1 --limit ≤ 50`.
- Профиль браузера с куками и подтверждённой 18+ живёт вне репозитория
  (`%LOCALAPPDATA%\opencode\ozon-profile`), первый вход — вручную.

## Решения по коду

- **Переиспользовать существующие функции**, новый код писать только для
  отсутствующего и держать «тонким» (`search` — оркестратор поверх `gather`,
  а не новый сборщик).
- Единственная точка выбора браузера — `browser.py::browser_kind` и
  `_chrome_override()` (инъекция CHROME в лаунчеры + моки в тестах).
- Чужой или неподтверждённый по identity процесс Chromium **никогда** не убивается
  (`BrowserOwnershipError`) — только ручное вмешательство. Убивать браузер можно
  со сверкой PID + cmdline + маркер.
- `Session.close()` не гасит браузер: закрывает вкладки кроме `pages[0]` и уводит
  её на `about:blank`.
- Recovery: recyclable (browser / renderer_failure) → перезапуск Chromium и повтор
  товара; non-recyclable (target / unknown) — только фиксация ошибки.
- TTL-кеш `raw.json`: файл берётся, если свежий по `collected_at_utc`,
  `incomplete != true`, совместима `schema_version` **и** `collector_version`
  равен текущей. Сравнение версий числовое (`tuple[int…]`): строковое
  `'1.10.0' < '1.9.0'` врёт. Файлы не удаляются, а перезаписываются.
- Нумерация разделов отчёта (`## N.` в `report.py`) зашита 1-7 и не
  перенумеровывается при пропуске раздела — на блок можно ссылаться стабильно.
- Дедуп ответов продавца — только на рендере Markdown; `*_raw.json` не меняется.
- `manifest` (`default_manifest`) аддитивный: новые поля разрешены, старые не
  переименовывать (resume сверяет `campaign_identity.url_sha256`).
- Имя кампании (`naming`) **не равно** `--match-title`: фраза фильтра берётся
  только из явного `--match-title`, `text=` из URL её не заменяет.

## Ловушки демона (супервизора кампаний)

- **`discovered_pids` ≠ собранные.** Список пополняется сразу после докрутки
  выдачи, ДО сбора. Поэтому «известные пиды» нельзя целиком выкидывать из
  очереди: товары, до которых воркеры не дошли (`SESSION_EXHAUSTED`,
  `BROWSER_DEAD`, конец прогона), выпадали навсегда — в логе было
  «пропущено 336 уже обработанных (осталось 0)» при 66 `raw.json` на диске.
  Разбор — `key_daemon.split_done_pending()`; `pending_pids()` показывает, что
  осталось без результата, в логе статуса и в `summarize()`.
- `SESSION_EXHAUSTED` — **soft** блок (пауза без `profile_cooldown` и без роста
  `storm_streak`); `SESSION_BLOCKED` / IP / нерешённый пазл — **hard**.
  Сомнение = hard. Шторм одного воркера ≠ шторм всей кампании.
- Сессия воркера имеет бюджет на весь прогон: `challenge 3, new_tab 3,
  browser_recycle 2, wall_clock 1800с`. Исчерпание → `SESSION_EXHAUSTED` → abort
  прогона; оставшиеся товары уходят в следующий прогон (см. первый пункт).
- `NORMAL_DONE` означает «воркеры отработали», а не «собрано всё». Признак
  недобора — 3 раунда подряд без новых валидных (`no-progress лимит`).
- URL кампании лежит в состоянии и валидируется на загрузке:
  markdown-обёртки и пунктуация чинятся, не-URL → `ValueError` → exit 2 **до**
  запуска браузера (иначе тихая потеря суток с `discovered=0`).

## Окна и фокус (замеры 2026-10-06)

- Окно браузера коллектора создаётся скрытым (SW_HIDE), затем свёрнутым без
  активации (`SW_SHOWMINNOACTIVE` + `WS_EX_NOACTIVATE` + `HWND_TOPMOST`).
- Chromium **сам** крадёт фокус на старте (foreground == chrome через 0.3-0.4 с
  даже при скрытом окне) и **сам** выводит окно из minimized в normal через
  ~30-40 с после старта. Ни SW_HIDE, ни `SW_SHOWMINNOACTIVE`, ни снятие
  `SetTopmost` это не лечит — источник внутри Chromium/Windows.
- Вернуть фокус нельзя: `AttachThreadInput` возвращает 0, `SetForegroundWindow`
  и `SwitchToThisWindow` отказаны. Работает только синтетический Alt.
- `ozon_collector/window_policy.py` умеет гасить такое окно (0.06 с) и возвращать
  фокус, но **выключен по умолчанию** (`OZON_WINDOW_GUARD=1` включает): окна
  браузеров коллектора — рабочие окна пользователя («трогай только свои»).
- Ручное открытие окна отличается от самовсплытия: `GetLastInputInfo` не
  учитывает ни программные `ShowWindow`, ни `SendInput`.

## Чего делать не нужно

Пользователь упростил проект до однократного сбора по запросу. Убрано и не
возвращается: `analyze` (аналитика, тональность, confidence), `compare`
(сравнение кандидатов), `validate` + `regression` (health-check и гейт по
истории), `watch` + `diff` (мониторинг изменений), `catalog` + `export` +
`migrate` (портфельная логика), история raw по датам. Ещё раньше — конфиги
категорий, regex-классификация плюсов/минусов, cron/nightly, baseline-регрессия.
